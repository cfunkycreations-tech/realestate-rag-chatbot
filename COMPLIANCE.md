## Verification limitations

The latest backend suite passed 204 tests; frontend lint, typecheck, 14 Vitest tests and production build passed. New shared/project memory, duplication, event-export, skills, global-pause, handoff, routine, chat, attachment, group chat, backup staging, tool policy, review queue, notices and follow-up UI flows were exercised at 1440px and 390px against disposable local installations; their screenshots are in `docs/screenshots/`. Browser tests use disposable fixture data and do not establish real-provider behavior.

Docker and PowerShell are unavailable in this environment, so Compose, `scripts/docker-smoke.ps1`, actual Docker volume upgrades, network isolation and phone-on-LAN access were not run. Scheduler DST and queued-slot restart have targeted tests, but production Docker recovery is unverified. MCP approvals, computer isolation/browser approval and computer kill-switch tests cannot pass because those features do not yet exist. Backup staging and a local restored-process boot were tested, but one-click restore and Compose restore remain unverified or absent. There is no proof that every external action is approval-gated. The existing local secret redaction is heuristic and does not guarantee removal of unknown secrets. Do not use this partial implementation for unattended or sensitive computer work.
