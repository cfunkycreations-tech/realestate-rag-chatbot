## Verification limitations

The latest backend suite passed 300 tests; frontend lint, typecheck, 17 Vitest tests and production build passed. New shared/project memory, duplication, event-export, skills, global-pause, handoff, routine, chat, attachment, mission/project file, workflow, Bot DM, search-approval, mention, computer workspace/permission/stop, group chat, connector, backup staging, tool policy, review queue, notices and follow-up UI flows were exercised at 1440px and 390px against disposable local installations; their screenshots are in `docs/screenshots/`. Browser tests use disposable fixture data and do not establish real-provider behavior.

Docker and PowerShell are unavailable in this environment; `scripts/verify-computer.bat` is provided to build a disposable Compose project and record real worker, offline route, desktop-frame, Playwright session, takeover, kill switch and workspace checks in `computer-verification.txt`. This fallback has not been run here. Compose, `scripts/docker-smoke.ps1`, actual Docker volume upgrades, network isolation and phone-on-LAN access were not run. Scheduler DST and queued-slot restart have targeted tests, but production Docker recovery is unverified. Computer shell approvals, snapshot validation and transfer were tested with mocks; the real worker passed a two-command local PID/network-namespace round trip, detached-process cleanup and in-flight cancellation. Docker isolation, resource limits and container cleanup have not been verified. Chromium sessions have experimental live viewing, per-action screenshots and takeover; browser sign-in and persistent cookies do not exist; optional HTTPS broker is unverified under Docker. A local headless Chromium/Playwright smoke test exercised the real action handler for file navigation, fill, selector click, text extraction and screenshot; it is not a sandbox or Docker test. Desktop startup, browser broker, model screenshots, session persistence and takeover are unverified under Docker. The computer stop is best effort and actual Docker behavior is unverified. MCP approval and local TLS fixture tests passed, but real-service compatibility is unverified. Backup staging and one-click restore were tested with a real local process and browser; Compose restore remains unverified. There is no proof that every external action is approval-gated. The existing local secret redaction is heuristic and does not guarantee removal of unknown secrets. Do not use this partial implementation for unattended or sensitive computer work.
