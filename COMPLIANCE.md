# Funk Bot — acceptance status

This is a snapshot of the implementation, not a security certification or a claim of full product parity. “Partial” means the described functionality exists but the broader acceptance area still has limits or lacks end-to-end verification. Model-dependent features depend on the configured gateway, model, tool support and budget. Real providers were not exercised in the tests below.

| # | Area | Status | Implemented and remaining limits |
|---|---|---|---|
| 1 | Bot identity and roster | Partial | Create, edit, delete and duplicate Bots, including identity, profile, sprite and budget. Routine definitions are duplicated paused, without history; skills are account-wide, not Bot-assigned. |
| 2 | Chat and attachments | Partial | Named chats with search, rename, delete, streaming and stop; text, text-readable PDF and re-encoded image attachments. Provider compatibility and all PDF/image formats are not established; Bot memory is shared across that Bot's chats, and missions use its default chat. |
| 3 | Memory | Partial | Owner-managed Bot, shared and project memory; direct-chat `!memory` controls and model-proposed Bot facts, reviewable by the owner. Facts are model-dependent; semantic recall and automatic shared/project proposals are not implemented. Forgetting a memory does not erase conversation or audit history. |
| 4 | Inbox and follow-ups | Partial | Persistent follow-ups, Bot notices, mentions and routine outcomes, with read/delete controls; pending tool approvals also appear in Inbox. Due indicators require an open app; follow-ups do not automatically continue work. |
| 5 | Bot delegation | Partial | Owner handoffs and Bot-proposed handoffs create receiver missions and recorded events. Directional Bot pairs can be pre-approved in Settings for automatic handoffs; other pairs require individual approval, and a handoff deny policy overrides pair approval. Receiver model runs use normal budget accounting and tool calls are audited. Delegation can still stop for other approvals, budget limits or errors; real-provider execution is unverified. |
| 6 | Mentions and slash skills | Partial | Direct chat supports skill invocation and autocomplete for Bots, groups, routines and connectors; group chat also supports mentions. Mentions provide bounded metadata, not automatic routing or permission to execute. Other composers do not offer mentions. |
| 7 | Group chat | Partial | Persistent group chat with Chief planning, sequential member replies, Bot memory, budgets, approvals, stop and events. Replies are not streamed, parallel mode is absent, and real-provider behavior is unverified. |
| 8 | Bot-to-Bot DMs | Partial | Owner-initiated persistent two-Bot exchanges with separate budgeted runs, memory, approvals, stop and Office events. Autonomous Bot-initiated DMs and streaming are not implemented. |
| 9 | Mission and project files | Partial | Owner uploads and individually approved Bot-authored text results, downloads, deletes and individually approved text sharing with model destinations. Files are not automatically supplied to Bots; authored attachments are text-only and uploads are not malware-scanned. |
| 10 | Routines and learning | Partial | Persistent cron/timezone schedules create approved, unattended mission occurrences, use normal budgets and tool approvals, retry failed occurrences once, and put success or final failure in Inbox. Budget uncertainty may block the retry, and a tool needing approval can still pause the mission. After three recent completed owner-created single-Bot missions, a budgeted model call judges semantic similarity from bounded requests, results and tool-call transcripts and drafts a suggestion for owner review and schedule approval. Candidate selection considers at most eight recent unmatched missions, so older repetitions can be missed; model classification/drafting can fail or be inaccurate. Scheduler runs in one backend worker; interrupted streams and real long-term deployment recovery are not fully verified. |
| 11 | Workflows | Partial | Owners can draft versioned workflows from completed missions and replay sequential steps with budgets and tool approvals. They are editable prompt-based steps, not recorded deterministic actions; outputs vary and interrupted replays fail. |
| 12 | Skills | Partial | Account skills, slash invocation, mission-derived drafts and limited Markdown/frontmatter import. Full SKILL.md/YAML ecosystem compatibility is not implemented. |
| 13 | Computer sandbox and workspace | Partial | Optional Docker computer service, bounded per-Bot data snapshots and owner file transfer. Funk reports that Docker checks passed on Funk's machine for shell, desktop, Playwright, takeover and kill switch. Docker isolation and resource guarantees were not independently verified in this sandbox. |
| 14 | Computer permissions and files | Partial | Default-deny per-Bot computer permission, owner-approved shell and desktop actions, bounded workspace snapshots and transfers. This is not unrestricted host filesystem access. Permissions and tool actions remain subject to configured controls. |
| 15 | Computer operation and stop | Partial | Desktop screenshots, vision-model actions, exclusive owner takeover and stale-action invalidation; stop, global pause and kill request worker termination. Funk reports these passed the machine checks above; termination is best effort and already completed actions cannot be undone. Sandbox-side tests use mocks and local Chromium, not Docker. |
| 16 | Browser | Partial | Playwright desktop actions and optional HTTPS broker with exact hostname allowlist and approval per host. Funk reports Playwright and takeover checks passed on Funk's machine. Browser sign-in and persistent cookies are absent; broker isolation is not a hardened security boundary and was not independently Docker-tested here. |
| 17 | Local machine access | Not implemented | Direct control of the owner's local machine is not provided; the optional computer service is a separate environment. |
| 18 | MCP connectors | Partial | Owner-configured HTTPS JSON/POST-SSE and local stdio MCP connectors, allowed tool lists, individually approved calls and audit. Local stdio commands are **unsandboxed and run with backend privileges**. OAuth, separate GET event streams, server-initiated requests and broad real-service compatibility are not established. |
| 19 | Web access and search | Partial | Public web fetch with host rules and SSRF checks; optional separately approved SearXNG-compatible HTTPS JSON search. Tests use fixtures, not a verified external search provider; arbitrary providers and search authentication are unsupported. |
| 20 | Approvals and policies | Partial | Owner tool policies, approval cards and audit; computer actions, searches, MCP and file shares retain individual approval. Approved directional Bot pairs can automatically hand off unless handoffs are denied. Policy changes cannot undo an action already started, and there is no proof every external action is gated. |
| 21 | Budgets and analytics | Partial | Model reservations, per-Bot/account budgets, usage, analytics and comparison Lab; routine learning and receiver runs use the same model accounting. Uncertain charges can block future runs until reconciled. Connector-side and computer charges are not accounted for. |
| 22 | Audit and global pause | Partial | Event and tool audit, JSON/CSV export and global pause for single-worker jobs. Stop is best effort and cannot undo remote actions. Exports can contain sensitive data; redaction is heuristic, not guaranteed. |
| 23 | Mobile and PWA | Partial | Responsive navigation and layouts, install guidance, an offline shell, and opt-in generic device notifications while the app is open. A 390px Chromium pass exercised navigation, key forms, spotlight, sidebar and settings; it is not proof of every state or physical-device behavior. Background Web Push and verified phone installation/LAN access are absent. |
| 24 | Backup and restore | Partial | Paused ZIP workspace export, validation and staged restore, with optional activation/restart and session rotation. Local process/browser round trips passed; Compose/Windows restore is unverified. Archives contain decryption keys and are not encrypted as a whole; OmniRoute and unrecognized files are excluded. |

## Verification

Latest run: **316 backend tests passed, 1 skipped**, with one warning; frontend lint, TypeScript, **17 Vitest tests**, and production build passed. A disposable local Chromium run at 390px checked all 13 main navigation views, five creation forms, Bot spotlight/chat, sidebar and all Settings tabs for page/control overflow. These are fixture-based checks, not real-provider, physical-phone or exhaustive interaction tests.

Funk independently reported the Docker computer checks above passed on Funk's machine. Docker and PowerShell were unavailable in this sandbox, so those results were not independently reproduced here. Model calls in tests use fake gateways; search and MCP tests use fixtures. The scheduler and autonomous missions can be interrupted by approvals, provider errors, budget safeguards, the bounded mission tool-round limit, pause or restarts. Do not interpret these results as a guarantee of unattended completion or isolation for sensitive work.
